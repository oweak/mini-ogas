## 2. Scope And Truth Boundary

The existing REST path remains authoritative. A heartbeat is validated and its
PostgreSQL fact plus deterministic envelope are committed to the transactional
Outbox together. A dedicated background worker is the only NATS publisher.

The NATS worker stores an idempotent transport receipt containing the complete
validated envelope in PostgreSQL. It does not reapply the business mutation.
This avoids duplicate event projections while proving publication, durable
consumption, schema validation, acknowledgement and PostgreSQL persistence.

Current organic runtime traffic is the v2 heartbeat adapter. The event,
command and audit publisher methods are executable, tested and live-gate
verified, but are not yet a replacement for their REST/domain mutation paths.

## 3. Runtime Topology

```text
Python SimPy node
  -> authenticated REST heartbeat
  -> Central authoritative validation and PostgreSQL fact + Outbox commit
  -> dedicated Outbox worker
  -> NATSPublisher strict shadow envelope
  -> NATS JetStream OGAS_V3_SHADOW
  -> durable pull consumer ogas-v3-postgres-worker
  -> PostgreSQL nats_shadow_receipts
```

The Go supervisor now manages twelve processes. `nats-server` is checked through
its official HTTP health endpoint with a session-agnostic third-party health
profile. All Mini-OGAS-owned services retain session-aware health checks.

## 5. Executable Message Contract

`app/core/nats_contracts.py` implements strict Pydantic models with
`extra="forbid"`. Each message has schema version `3.0`, a UUID message ID,
message type, source, node, UTC timestamps, correlation ID, run ID, sequence
and a type-specific data object.

| Message | Subject |
| --- | --- |
| Event | `ogas.events.{event_type}.{node_code}` |
| Heartbeat | `ogas.heartbeats.{node_code}` |
| Command | `ogas.commands.{node_code}` |
| Audit | `ogas.audit.{resource_type}` |

Subject tokens reject wildcards and dot injection. Heartbeat v2 is adapted to
the v3 contract. The known live v2 value `runtime_source=node-agent` is mapped
explicitly to v3 `live`; no unknown value is silently coerced.

Deterministic IDs plus the `Nats-Msg-Id` header provide JetStream duplicate
suppression. PostgreSQL additionally enforces `message_id` as the primary key.

## 6. JetStream And Worker Policy

Stream `OGAS_V3_SHADOW` uses file storage with:

- four explicit subject families;
- seven-day maximum age;
- 4 GiB maximum bytes;
- 256 KiB maximum message size;
- two-minute duplicate window;
- one local replica for the v3.0.1 development phase.

The durable consumer uses explicit ACK, 30-second acknowledgement wait, five
maximum deliveries and 1,000 maximum pending acknowledgements. Startup verifies
that an existing durable consumer has the exact required subject filters and
explicit acknowledgement policy. Invalid envelopes are terminated rather than
written. Persistence failures are negatively acknowledged for redelivery.

An empty pull timeout is treated as an idle poll, not a transport failure. A
regression test covers both the `nats-py` timeout class and Python 3.13's base
`asyncio.TimeoutError` behavior.

## 7. Failure And Recovery Behavior

NATS connection attempts are bounded. If NATS is absent, Central REST remains
available while the dedicated worker reports degraded readiness, retains Outbox
rows and retries through its connection manager.

Health semantics are deliberately split:

- `/health.status=ok` is process liveness for the supervisor;
- `/health.overall_status=degraded` reports optional integration readiness;
- `/health.nats.status=degraded` reports the specific transport state.

This prevents an unavailable optional transport from causing a supervisor
restart loop. REST remains authoritative and returns its own result plus the
shadow transport result.

Rollback is executable:

```powershell
.\scripts\start-supervisor.ps1 -ReplaceRunning -DisableNats
```

This disables Central publication and consumption without changing the REST or
PostgreSQL fact path.

## 9. Acceptance Decision

| Requirement | Result | Evidence |
| --- | --- | --- |
| NATS unavailable is explicit degraded, not a crash | PASS | Independent process unavailable-path gate |
| Event publishes, consumes and persists in PostgreSQL | PASS | JetStream live gate and receipt query |

| No schema-free arbitrary JSON | PASS | Strict Pydantic envelope and worker validation |

multi-host edge nodes, TLS/mTLS, NATS HA or NATS as the authoritative fact path.
